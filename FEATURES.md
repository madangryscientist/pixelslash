# PixelSlash features

Checked against main at dba45b9 on 2026-11-20.

## Command line
- `npm-cli`: install the command line tool from npm as `@slashsuite/pixelslash`; the command is `pixelslash` and it runs on Bun. How to reach it: `npm i -D @slashsuite/pixelslash`. Source: `packages/cli/package.json`.
- `cli-version`: print the installed version. How to reach it: `pixelslash --version`. Source: `packages/cli/src/run.ts:214`.
- `compare-two-pngs`: compare two PNG shots, Main and Branch, and write a `report.html` that shows what changed, with no browser. How to reach it: `pixelslash --live-png PATH --local-png PATH [--out DIR]`. Source: `packages/cli/src/args.ts:15`.
- `compare-two-urls`: shoot two URLs that are already running and compare them; it starts no dev server. How to reach it: `pixelslash --live URL --local URL`. Source: `packages/cli/src/args.ts:15`.
- `compare-two-png-dirs`: compare two folders of PNGs, one per route, in one run. How to reach it: `pixelslash --live-png-dir DIR --local-png-dir DIR (--ds DIR | --file FILE_KEY)`. Source: `packages/cli/src/args.ts:15`.
- `pair-mode-options`: tune the pair run with `--routes FILE` (a list of paths), `--out DIR`, `--width PX`, `--browser chromium|firefox|webkit`, `--label TEXT`, `--threshold 0..1`, `--min-changed-pixels N`, `--min-changed-ratio 0..1`, `--merge-distance PX`, `--min-region-area PX`, `--noise-amplitude 0..1`, `--max-shift 0..1` and `--ignore x,y,w,h` (repeatable). How to reach it: `pixelslash --live URL --local URL --routes FILE`. Source: `packages/cli/src/args.ts`.
- `design-system-judge`: check each shot against a design system's component images (a folder, or Figma frames by file key) with a local vision model; with no judge installed it prints `skip: no judge` and reports no violations. How to reach it: `pixelslash ... --ds DIR`, or `--file FILE_KEY --token-path PATH`. Source: `packages/cli/src/args.ts:15`. Source: `packages/engine/src/judge.ts`. Source: `packages/engine/src/figma.ts`.
- `init`: write a `pixelslash.config.ts` from a few questions, and add the snapshot folders to `.gitignore`; each flag answers one question, `--yes` takes the defaults, and an existing config is kept unless `--force`. How to reach it: `pixelslash init [--url URL | --storybook URL] [--routes PATH,...] [--viewports WxH,...] [--themes THEME,...] [--server URL] [--project NAME] [--yes] [--force]`. Source: `packages/cli/src/init.ts:11`.
- `capture`: shoot every route of the config into a snapshot folder, and optionally upload the result in the same run. How to reach it: `pixelslash capture [--config FILE] [--out DIR] [--only NAME]... [--concurrency N] [--json]`, or with `--upload [--server URL] [--token-path PATH] [--project ID|NAME] [--subproject NAME] [--base BRANCH] [--branch NAME] [--pr N] [--flake-retries N] [--judge]`. Source: `packages/cli/src/capture.ts:32`.
- `compare-snapshot-dirs`: compare two `pixelslash capture` snapshot folders, with no design system and no server; a shot the diff cannot measure is marked `not compared` and the run exits 7. How to reach it: `pixelslash compare MAIN_DIR BRANCH_DIR [--out DIR]`. Source: `packages/cli/src/compare.ts:17`.
- `import-pngs`: turn a folder of PNGs from any screenshot tool into a snapshot folder that `pixelslash upload` takes, with Android and iOS shots (from Maestro) labelled by device and scale; a `<name>.metrics.json` beside a PNG travels with it. How to reach it: `pixelslash import PNG_DIR [--out DIR] [--viewport WxH] [--theme light|dark] [--renderer LABEL] [--platform web|android|ios --device "<label>" --scale N]`. Source: `packages/cli/src/import.ts:11`. Source: `packages/engine/src/import-pngs.ts`.
- `upload-to-review-app`: send a snapshot folder to a review app, which diffs it against the default branch and holds the build for review; `--brief FILE` or `--brief-text TEXT` adds your own words on what the build means to change, `--judge` adds one sentence per changed shot from the local vision model, `--flake-retries N` re-shoots a changed shot, and `--wait` waits for the review as `pixelslash status --wait` does. How to reach it: `pixelslash upload DIR [--server URL] [--token-path PATH] [--project ID|NAME] [--subproject NAME] [--base BRANCH] [--branch NAME] [--pr N] [--brief FILE | --brief-text TEXT] [--config FILE] [--flake-retries N] [--concurrency N] [--judge] [--wait [--timeout DURATION] [--interval DURATION]]`. Source: `packages/cli/src/upload.ts:37`.
- `upload-skipped`: record that a commit captured nothing on purpose, as a passed build with no shots, so the commit still gets its status; it changes no baseline. How to reach it: `pixelslash upload --skipped [--server URL] [--token-path PATH] [--project ID|NAME] [--subproject NAME] [--base BRANCH] [--branch NAME] [--pr N] [--config FILE]`. Source: `packages/cli/src/upload.ts:37`. Source: `packages/cli/src/upload-skipped.ts`.
- `check-local`: shoot the config's routes against an app that is already up, fetch the baselines the server would pick for this commit, and write the same report `compare` does, uploading nothing. How to reach it: `pixelslash check [--config FILE] [--out DIR] [--base BRANCH] [--only NAME]... [--server URL] [--token-path PATH] [--project ID|NAME] [--flake-retries N] [--concurrency N] [--json]`. Source: `packages/cli/src/check.ts:31`.
- `dev-mode`: re-shoot one route or story on every save and compare it with the previous iteration, a pin or main's baselines, on a live local page, uploading nothing; a target with a spec, reference PNGs or Figma frames shows them beside the shot, and `--judge` lists how the shot differs. Keys: `r` run, `p` pin, `u` unpin, `m` main or previous, `f` refetch refs, `q` quit. How to reach it: `pixelslash dev [TARGET | --url URL] [--viewport WxH|NAME] [--theme light|dark] [--watch PATH]... [--against main|previous] [--judge [--ds DIR]] [--refresh-refs] [--figma-token-path PATH] [--once] [--json] [--config FILE] [--server URL] [--token-path PATH] [--project ID|NAME] [--base BRANCH]`. Source: `packages/cli/src/dev.ts:19`.
- `dev-subcommands`: read the latest dev iteration, pin or unpin one, and print a target's spec and references. How to reach it: `pixelslash dev latest [TARGET] [--json]`, `pixelslash dev pin [ID] [--json]`, `pixelslash dev unpin [ID] [--json]`, `pixelslash dev spec [TARGET] [--json] [--refresh-refs] [--viewport WxH|NAME] [--theme light|dark] [--figma-token-path PATH] [--config FILE]`. Source: `packages/cli/src/dev.ts:19`.
- `install-browser`: download the Playwright browser the capture needs. How to reach it: `pixelslash install-browser [chromium|firefox|webkit|all]`. Source: `packages/cli/src/run.ts:192`.
- `login`: store a personal token (`psu_...`) for a server, pasted at a prompt or piped on stdin, in `~/.config/pixelslash/credentials.json`. How to reach it: `pixelslash login [--server URL] [--config FILE]`. Source: `packages/cli/src/account.ts:15`.
- `logout`: remove the stored token for a server. How to reach it: `pixelslash logout [--server URL] [--config FILE]`. Source: `packages/cli/src/account.ts:17`.
- `whoami`: show which server the token is for and who it acts as. How to reach it: `pixelslash whoami [--server URL] [--token-path PATH] [--config FILE] [--json]`. Source: `packages/cli/src/account.ts:18`.
- `list-builds`: list a project's builds, newest first, optionally on one branch. How to reach it: `pixelslash builds [--branch NAME] [--limit N] [--server URL] [--token-path PATH] [--project ID|NAME] [--config FILE] [--json]`. Source: `packages/cli/src/builds.ts:15`.
- `show-build`: show one build, or the newest with `latest`. How to reach it: `pixelslash build ID|latest [--branch NAME] [--server URL] [--token-path PATH] [--project ID|NAME] [--config FILE] [--json]`. Source: `packages/cli/src/builds.ts:16`.
- `build-status`: read a build's review state (the one `upload` recorded, a commit's or a branch's newest), and with `--wait` hold a CI job until a person has decided; exit 0 accepted or nothing changed, 4 rejected, 5 still waiting, 3 the server refused or did not answer, or the build errored or its state is unknown. How to reach it: `pixelslash status [--build ID | --commit SHA | --branch NAME] [--dir DIR] [--wait [--timeout DURATION] [--interval DURATION]] [--server URL] [--token-path PATH] [--project ID|NAME] [--config FILE] [--json]`. Source: `packages/cli/src/status.ts:13`.
- `parity-check`: compare the layout metrics of every web, Android and iOS twin pair in a build, or, with `--release android|ios`, fail on any stale twin or drifting pair before a native release; exit 8 on drift. How to reach it: `pixelslash parity --build ID [--manifest PATH] [--server URL] [--token-path PATH] [--project ID|NAME] [--config FILE] [--json]` or `pixelslash parity --release android|ios [--project ID|NAME] [--manifest PATH] [--server URL] [--token-path PATH] [--config FILE] [--json]`. Source: `packages/cli/src/parity.ts:27`. Source: `packages/cli/src/parity-pairs.ts`.
- `list-flakes-cli`: list a project's open flaky shots. How to reach it: `pixelslash flakes [--server URL] [--token-path PATH] [--project ID|NAME] [--config FILE] [--json]`. Source: `packages/cli/src/flake.ts:38`.
- `flaky-shot-detection`: re-shoots each changed shot and flags it as flaky when the shots disagree; the count is `--flake-retries N`, else `flake.retries` in the config, else 2, and 0 turns it off. How to reach it: `pixelslash upload DIR --flake-retries N`, `pixelslash capture --upload --flake-retries N` or `pixelslash check --flake-retries N`. Source: `packages/engine/src/recapture.ts`. Source: `packages/cli/src/upload.ts`.
- `reproduce-flake`: reproduce one flaky shot locally by shooting it several times and diffing each run with the first (exit 0 stable, 6 unstable); `--suggest` shows the config changes that would fix it, `--write` writes the one you pick (JSON configs only), and `--resolve` marks it resolved on the server after a stable run. How to reach it: `pixelslash flake ID [--runs N] [--out DIR] [--write | --suggest] [--resolve [--note TEXT]] [--json] [--server URL] [--token-path PATH] [--project ID|NAME] [--config FILE]`. Source: `packages/cli/src/flake.ts:39`.
- `project-create-list`: create a project (or a subproject with `--parent`) by name, which is safe to run twice, and list the projects a token reaches. How to reach it: `pixelslash project create NAME [--org NAME] [--parent PROJECT] [--server URL] [--token-path PATH] [--config FILE] [--json]` and `pixelslash project list [--server URL] [--token-path PATH] [--config FILE] [--json]`. Source: `packages/cli/src/project.ts:13`.
- `config-file`: describe a project in `pixelslash.config.ts` (or JSON): `baseUrl`, a `start` command and `setup` script, `routes`, `variants` (viewport, theme, browser), `diff` options, `ignore` areas, a `flaky` policy, `flake.retries`, `stabilise` settings, `features` for `pixelslash dev`, `composition`, `metrics`, `concurrency` and `upload` settings. How to reach it: `pixelslash capture --config FILE`. Source: `packages/engine/src/config.ts`.
- `storybook-stories`: shoot every story of a running Storybook from its index, with no route list. How to reach it: `storybook` in the config, or `pixelslash init --storybook URL`. Source: `packages/engine/src/config-storybook.ts`. Source: `packages/engine/src/storybook.ts`.
- `ignore-and-redact`: leave an area out of the diff while still showing it, or paint over an area (a CSS selector or a fixed rectangle) before the PNG is written. How to reach it: `ignore` and `redact` in the config, or `--ignore x,y,w,h` in the pair mode. Source: `packages/engine/src/config-areas.ts`.
- `accessibility-checks`: run axe-core on each settled page and keep the WCAG A and AA violations with the shot, listing those that are new on Branch; this never changes the exit code. How to reach it: `"a11y": true` in the config. Source: `packages/engine/src/a11y.ts`. Source: `packages/engine/src/config.ts`.
- `layout-metrics`: write each shot's layout metrics from its `[data-part]` elements beside the PNG, for the parity check. How to reach it: `"metrics": true` in the config. Source: `packages/engine/src/metrics-walk.ts`. Source: `packages/engine/src/config.ts`.
- `composition-check`: report at capture every element styled outside the design-system library a project builds its pages from. How to reach it: `composition` in the config. Source: `packages/engine/src/composition.ts`. Source: `packages/engine/src/config-composition.ts`.
- `exit-codes`: fixed exit codes for CI: 0 a finished run, 1 new design-system violations or a failed run, 2 a usage error, 3 the server refused or did not answer (for `status`, also a build that errored or whose state is unknown), 4 rejected, 5 still waiting, 6 an unstable flake, 7 a crash or a shot it could not diff, 8 parity drift. How to reach it: the exit status of any `pixelslash` command. Source: `packages/cli/src/failure.ts`. Source: `packages/cli/src/api.ts`. Source: `packages/cli/src/status.ts`. Source: `packages/cli/src/flake.ts`. Source: `packages/cli/src/parity-pairs.ts`.
- `environment-variables`: set the token with `PIXELSLASH_TOKEN`, the server with `PIXELSLASH_SERVER`, cap parallel diffs with `PIXELSLASH_DIFF_CORES`, send a crash or an `UPLOAD FAILED` run (never shots) to Sentry with `PIXELSLASH_SENTRY_DSN` and name its environment with `PIXELSLASH_SENTRY_ENVIRONMENT` (default `cli`), and record the capture image in each shot's fingerprint with `PIXELSLASH_IMAGE_DIGEST` or `PIXELSLASH_IMAGE_VERSION`. How to reach it: the environment of any `pixelslash` command. Source: `packages/cli/src/remote.ts`. Source: `packages/engine/src/diff-cores.ts`. Source: `packages/cli/src/sentry.ts`. Source: `packages/engine/src/sentry-scrub.ts`. Source: `packages/engine/src/fingerprint.ts:39`.
- `engine-internal`: `packages/engine` (`@slashsuite/pixelslash-engine`) holds capture, the diff, the judge, Figma rasters and the report; it is internal, marked private, and not installed by users on its own. How to reach it: through `pixelslash` and `@slashsuite/pixelslash-playwright`. Source: `packages/engine/package.json`.
- `wasm-diff-engine`: the pixel diff is a Rust crate compiled to WebAssembly (`diff.wasm`), loaded by the command line tool and the review app; the crate is internal, not published, and not installed by users on its own. How to reach it: every diff the tool runs. Source: `engines/wasm/Cargo.toml`. Source: `packages/engine/src/diff-module.bun.ts`. Source: `packages/engine/src/diff-module.workerd.ts`.

## Review app API
- `api-v1`: an HTTP API under `/api/v1` that takes a CI, org or personal token, and may still change while PixelSlash is in alpha. How to reach it: `https://pixelslash.dev/api/v1/...` or your own server. Source: `apps/web/src/api/handler.ts:211`.

- `api-upload`: start a build, add shots one at a time or as a batch of known images, list which images the server already holds, and finalize the build. How to reach it: `POST /api/v1/builds`, `PUT /api/v1/builds/:id/snapshots`, `POST /api/v1/builds/:id/snapshots/batch`, `POST /api/v1/builds/:id/known`, `POST /api/v1/builds/:id/finalize`. Source: `apps/web/src/api/handler.ts:213`.
- `api-baselines`: the baselines a build gets for a list of shot keys, or the ones a build at a given commit would get now, creating nothing. How to reach it: `POST /api/v1/builds/:id/baselines`, `POST /api/v1/baselines`. Source: `apps/web/src/api/handler.ts:243`.
- `api-projects`: list the projects a token reaches, create one by name (or a subproject), and link a project to its twin on another platform. How to reach it: `GET /api/v1/projects`, `POST /api/v1/projects`, `PUT /api/v1/projects/:id/twin`. Source: `apps/web/src/api/handler.ts:247`.

How to reach it: `GET /api/v1/projects/:id/builds`, `GET /api/v1/builds/:id`, `GET /api/v1/builds/:id/parity`, `POST /api/v1/builds/:id/accept-all`. Source: `apps/web/src/api/handler.ts:262`.
- `api-snapshots`: read one shot with short-lived image URLs, and accept or reject it. How to reach it: `GET /api/v1/snapshots/:id`, `POST /api/v1/snapshots/:id/review`. Source: `apps/web/src/api/handler.ts:278`.
- `api-detection-flags`: list a project's flagged mis-detections, and mark one as exported. How to reach it: `GET /api/v1/projects/:id/detection-flags`, `POST /api/v1/detection-flags/:id/exported`. Source: `apps/web/src/api/handler.ts:263`.
